IA del sito SYSEM

Questa pagina descrive in modo più dettagliato l'architettura dell'assistente SYSEM: interfaccia web, servizi back-end, persistenza dei dati e collegamento al modello AI.

Front-end: index.html

Il front-end è una pagina statica: HTML, CSS e JavaScript sono nello stesso file. Mostra la chat, raccoglie il messaggio e chiama il back-end remoto pubblicato all'indirizzo https://gianluca-ai-ten.vercel.app/api.

Back-end: Python e Flask

Il back-end è in api/main.py. È un'applicazione Flask con endpoint per stato, autenticazione, profilo, cronologia e chat: /api/health, /api/auth/..., /api/profile, /api/history e /api/chat.

Flask è un framework web per Python: permette di trasformare funzioni Python in indirizzi raggiungibili dal browser o dal front-end. In questa applicazione riceve le richieste HTTP, legge o salva dati nel database, prepara le chiamate verso Groq e restituisce risposte JSON alla pagina.

Database: SQLite e Supabase

api/database.py gestisce la persistenza dei dati in due modalità. In ambiente locale usa un database SQLite con le tabelle dedicate al profilo dell'assistente, alla cronologia delle conversazioni e alle preferenze. In deploy può collegarsi a Supabase tramite API REST. Lo script scripts/setup_db.py inizializza la base dati e carica le informazioni di partenza dai file JSON del profilo.

Supabase è un servizio cloud che fornisce un database PostgreSQL e API pronte per leggere e scrivere dati da un'applicazione web. In questo caso serve quando l'assistente è pubblicato online: invece di dipendere solo da un file SQLite locale, il back-end può salvare profilo, preferenze e conversazioni su un database raggiungibile dal deploy.

Connessione a Groq

In api/main.py la funzione ask_groq() prepara i messaggi, legge la variabile GROQ_API_KEY e invia una richiesta POST a https://api.groq.com/openai/v1/chat/completions, usando il modello openai/gpt-oss-120b.

Flusso reale della richiesta

  1. L'utente apre la pagina dell'assistente e scrive la domanda.
  2. Il front-end controlla che l'API sia raggiungibile e invia una richiesta HTTP.
  3. Il back-end autentica la chiamata e costruisce la richiesta verso Groq.
  4. Groq restituisce la risposta del modello al back-end.
  5. Il back-end restituisce il JSON e il front-end aggiorna la conversazione.
